Interpretation: Add improved substantially and consistently (rest() was
the path that called std::map::operator[]/lower_bound to create a new
tree node per new price level -- exactly the allocation-heavy operation
PriceLadder eliminates). Cancel and Modify improved only marginally,
inside or near run-to-run noise. Working hypothesis (not confirmed with
hardware counters -- WSL2 does not expose the PMU, verified separately:
`perf stat -e cycles,instructions` reports `<not supported>` in this
environment): cancel's cost was never dominated by the container's
traversal algorithm, but by a cache miss fetching an Order/PriceLevel
that had gone cold since it was last touched. Replacing a pointer-chasing
tree lookup with an array-index computation removes the traversal and
allocation cost, but doesn't change whether the resulting memory access
is a cache hit or miss -- so the operations that were allocation-bound
(Add, creating new levels under load) improved, and the operation that
was already memory-latency-bound on both implementations (Cancel) did
not.
